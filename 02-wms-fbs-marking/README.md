# Анализ FBS-сборки и инвентаризации

## Запуск

Требуется PHP 8.1 или новее:

```bash
php analyze.php
```

Скрипт читает исходные файлы из `data/` и перезаписывает четыре отчёта в `output/`:

- `picking_list.csv` — маршрутный лист подбора;
- `unfulfillable_tasks.csv` — задания, для которых не хватает остатков;
- `assembly_control.csv` — ошибки и успешные проверки сборки;
- `inventory_discrepancies.csv` — расхождения пересчёта с классификацией.

CSV записываются с разделителем `;`, в UTF-8 с BOM для открытия в Excel. Скрипт не изменяет входные данные и завершает работу с кодом `1` при ошибке чтения или нарушении базовой целостности данных.

## Принятые решения

### Лист подбора

Остаток распределяется сначала заданиям с ближайшим `ship_by`, при одинаковом сроке — по `task_id`. Задание резервируется атомарно: если хотя бы одной позиции не хватает, частичный подбор для него не создаётся, а остаток может получить следующее полностью обеспеченное задание. Внутри товара расходуются ячейки в естественном порядке, после чего весь лист сортируется по ячейке — кладовщик проходит склад один раз.

По этим данным все обеспеченные задания можно собрать, кроме `T-5008`: две единицы `WH-2008` отданы более срочному `T-5007`, поэтому для `T-5008` не хватает одной единицы. В листе подбора получилось 14 строк.

### Контроль сборки

Для каждого задания проверяются количество и состав товаров. Для маркированного товара обязателен КИЗ с префиксом `01` + `0` + EAN-13 + `21` и непустым серийным номером; дополнительно КИЗ должен быть уникален во всём журнале. КИЗ у немаркированного товара считается предупреждением.

Результат:

- `T-5001` и `T-5003` используют один КИЗ повторно;
- в `T-5002` вместо `WH-2010` отсканирован `WH-2011`;
- для маркированного `WH-2006` в `T-5005` отсутствует КИЗ;
- в `T-5006` лишняя единица `WH-2011`;
- в `T-5008` отсутствуют все три ожидаемые единицы;
- в `T-5004` КИЗ содержит GTIN другого товара;
- только `T-5007` собрано корректно.

### Инвентаризация

Отсутствие строки пересчёта не приравнивается к нулю: ячейка `A-02-02` с 12 единицами `WH-2009` помечена `NOT_COUNTED` и должна быть пересчитана. Две единицы `WH-2006` отсутствуют в `A-01-05`, но найдены в `B-01-02`; общий остаток совпадает, поэтому это ошибка размещения, а не недостача. Подтверждена недостача трёх `WH-2004` в `A-01-04`. Три скана неизвестного штрихкода в `C-03-01` нельзя считать обычным излишком до идентификации товара.

## Как не допускать ошибок до отгрузки

Терминал сборщика должен принимать скан только в контексте открытого задания, сразу отклоняя чужой товар, лишнее количество и повторный КИЗ. Закрывать задание следует только после серверной проверки полного состава и КИЗ всех маркированных единиц. Для дефицитного товара система должна резервировать остаток по сроку отгрузки до начала физической сборки. Перемещение между ячейками нужно оформлять обязательным сканированием ячейки-источника и ячейки-получателя.
